# .agent.md - Configuración y Especialización de Agentes para Hestia

## 👥 Tipos de Agentes Recomendados

### 1. **Backend Agent** (Rails Development)
**Especialización**: Modelos, Controllers, Migraciones, APIs

**Instrucciones Específicas**:
- Siempre ejecutar tests después de cambios en modelos
- Respetar autorización con Pundit en autorizaciones
- Usar `includes()` y `preload()` para evitar N+1
- Comandos útiles:
  ```bash
  rails console          # Debugging
  rails db:migrate      # Aplicar migraciones
  bin/rubocop -a        # Auto-fix linting
  rails test            # Ejecutar suite
  ```

**Áreas de Expertise**:
- `app/models/` - Lógica de negocio
- `app/controllers/` - Request handling
- `config/routes.rb` - Routing
- `db/migrate/` - Schema changes
- `app/policies/` - Authorization

---

### 2. **Frontend Agent** (Views & Styling)
**Especialización**: Views ERB, JavaScript, CSS Bootstrap

**Instrucciones Específicas**:
- Usar `app/assets/stylesheets/` para estilos custom
- Stimulus controllers en `app/javascript/controllers/`
- Reutilizar componentes Bootstrap
- Verificar accesibilidad WCAG

**Áreas de Expertise**:
- `app/views/` - HTML/ERB templates
- `app/javascript/` - Stimulus controllers
- `app/assets/` - CSS y assets
- `public/` - Archivos estáticos

---

### 3. **DevOps/Testing Agent**
**Especialización**: Tests, CI/CD, Docker, Deployment

**Instrucciones Específicas**:
- Mantener test coverage > 80%
- Ejecutar `bin/brakeman` para security
- Validar Dockerfile antes de deploy
- Verificar migrations son reversibles

**Áreas de Expertise**:
- `test/` - Test suites
- `Dockerfile` - Containerization
- `Procfile.dev` - Development setup
- `config/environments/` - Environment config

## 🎯 Reglas Globales para Todos los Agentes

### ✅ DEBE

1. **Autorización**
   - Siempre usar `authorize @resource` en controllers
   - Nunca bypassear Pundit policies
   - Validar `policy_scope()` en `index` actions

2. **Testing**
   - Agregar tests para nueva feature
   - Mínimo: 1 unit test + 1 controller test
   - Ejecutar suite completa antes de considerar done

3. **Performance**
   - Revisar queries con `.includes()` para relations
   - Usar `select()` para limitar columnas si es posible
   - Evitar loops en views

4. **Seguridad**
   - Usar credentials encriptadas, nunca hardcode secrets
   - Validar input del usuario
   - Escapar output en views (ERB lo hace por defecto)

5. **Código Limpio**
   - Pasar `bin/rubocop -a` sin warnings
   - Máximo 100 líneas por método
   - Nombres descriptivos en variables/métodos

### ❌ NO DEBE

1. Modificar migraciones después de `db:migrate`
2. Skipear `before_action :authenticate_user!` en controllers públicos
3. Usar SQL crudo sin parameterization
4. Dejar TODO comments sin resolver
5. Hardcodear valores magic

## 🔄 Workflow Recomendado

### Cuando Comience una Tarea

```
1. Lee AGENTS.md para entender proyecto
2. Lee .instructions.md para setup operacional
3. Ejecuta: rails test (baseline)
4. Crea rama: git checkout -b feature/descriptor
5. Implementa cambios con TDD
6. Corre: bin/rubocop -a
7. Corre: bin/brakeman
8. Corre: rails test (verificar pase)
9. Commit y push para review
```

### Checklist Pre-Commit

- [ ] Tests agregados y pasando
- [ ] Código pasa rubocop
- [ ] Sin warnings de brakeman
- [ ] Migraciones son reversibles
- [ ] Autorización validada con Pundit
- [ ] N+1 queries revisadas
- [ ] Commit message descriptivo
- [ ] Branch actualizado con main

## 🚨 Áreas Sensibles (High-Risk)

### Cambios en Models
- ⚠️ Cambiar tipo de dato en BD (migration + data backfill)
- ⚠️ Renombrar columna (migration con alias)
- ⚠️ Eliminar columna (deprecate primero)
- ✅ SIEMPRE: agregar tests

### Cambios en Autorización
- ⚠️ Modificar Pundit policies
- ⚠️ Cambiar roles de usuarios
- ⚠️ Alterar scope de queries
- ✅ SIEMPRE: probar con todos los roles

### Cambios en Rutas
- ⚠️ Cambiar URLs existentes (break links)
- ⚠️ Alterar orden de namespaces
- ✅ SIEMPRE: mantener backward compatibility

## 🧠 Knowledge Base

### Conceptos Clave en Hestia

**Tenant** (inquilino)
- Usuario con acceso a portal
- `role: :tenant` en User model
- Solo ve su contrato y pagos

**Gestor** (real estate agent)
- Gestiona propiedades de su empresa
- `role: :gestor` en User model
- Puede crear contracts y track payments

**Admin**
- Acceso total
- `role: :admin` en User model
- Puede ver todas las empresas y propiedades

### Ciclo de Vida de Contrato
```
Property created → Tenant assigned → Contract created → 
Charges generated → Tenant pays → Status updated
```

## 📞 Escalation Path

Si durante desarrollo encuentras:

**❓ Incertidumbre sobre**:
- Arquitectura → Lee `AGENTS.md` sección arquitectura
- Setup/Dev → Lee `.instructions.md`
- Autorización → Revisa `app/policies/`
- Testing → Revisa `test/` ejemplos

**🐛 Bug en**:
- Tests → Ejecuta con `-v` flag para ver qué falló
- Models → Usa `rails console` para debugar
- Controllers → Agregar `binding.pry` (requiere pry-rails)
- Views → Inspeccionar en browser dev tools

**📈 Performance**:
- Queries lentas → Query analyzer en logs o bullet gem
- Asset lento → Compilar CSS con `npm run build:css`
- Page lento → Detectar N+1 en `.includes()`
